# Implementation Plan: Quantizer

**Branch**: `025-quantizer` | **Date**: 2026-05-30 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/025-quantizer/spec.md`

## Summary

Add a `Quantizer` utility component that accepts a continuously varying CV input and snaps it to the nearest pitch in a user-selected musical scale and root key, outputting a quantized CV signal at control rate. An optional gate/trigger input enables rhythmically locked pitch updates. The component reuses the existing `MusicalScale` scale interval data and follows the same `SynthComponent` + `ConstantSourceNode` CV output pattern established by `ChordFinder` and `Collider`.

## Phase 0: Research

**Status**: Complete — see [research.md](research.md)

Key decisions:
1. Pre-computed sorted MIDI pitch table rebuilt on config change; linear scan at quantization time
2. New `QuantizerScaleType` enum (superset of Collider's) — 006 contracts unchanged
3. Control-rate CV polling via visual update scheduler (same as Collider/ChordFinder)
4. Trigger rising-edge detection: previous gate value tracked in component state
5. Note label: `ctx.fillText()` in `CanvasComponent`, updated each scheduler tick
6. Tie-breaking: higher pitch wins (ascending table scan, strictly-less-than comparison)
7. `ComponentType.QUANTIZER` added to `src/core/types.ts`

- `cvToMidi(cv)` / `midiToCv(midi)` — CV ↔ MIDI conversions
- `serializeQuantizerConfig(config)` / `deserializeQuantizerConfig(params)`
